# 로그인은 JWT로 하고, 로그아웃은 폐기 목록으로 처리한다

로그인하면 서버가 HS256으로 서명한 JWT(사용자 ID, 아이디, 만료 시각, 토큰 ID `jti`)를 돌려주고, 웹은 이를 브라우저 저장소에 두었다가 요청의 `Authorization: Bearer` 헤더에 붙인다. 서버 세션+쿠키보다 웹(`API_BASE_URL`로 다른 출처에서 서빙될 수 있음)과 서버를 나눠 띄우는 로컬 개발 구성에서 CORS·쿠키 설정 없이 그대로 동작하고, 검증에 DB 조회가 거의 필요 없다. 대신 JWT만으로는 로그아웃해도 토큰이 만료 전까지 살아 있으므로, 로그아웃할 때 `jti`를 만료 시각과 함께 폐기 목록 테이블에 넣고 인증할 때마다 확인한다. 폐기 목록은 만료가 지난 항목을 지워 작게 유지한다.

브라우저 WebSocket은 헤더를 붙일 수 없어, 송출 WebSocket은 첫 메시지(송출 시작)에 토큰을 싣는다. 주소 질의 문자열에 넣지 않아 프록시·접속 로그에 토큰이 남지 않는다. 댓글 실시간 WebSocket은 읽기 전용이라 인증하지 않고, 댓글 쓰기·삭제는 헤더로 인증하는 HTTP API로 한다.

## Consequences

- 서명 키 `JWT_SECRET`은 실행 환경에만 둔다. 비우면 서버가 시작할 때마다 임시 키를 만들어(재시작하면 모두 로그아웃) 비밀 값 없이도 실행·평가할 수 있다.
- 토큰을 브라우저 저장소에 두므로 XSS에 취약할 수 있다. 화면은 Dioxus가 텍스트를 이스케이프해 그리며, 사용자 입력을 HTML로 넣지 않는다.
- 리프레시 토큰은 없다. 유효 시간(`JWT_TTL_SECS`, 기본 24시간)이 지나면 다시 로그인한다.
- 비밀번호는 argon2id 해시(PHC 문자열)로만 저장한다.
